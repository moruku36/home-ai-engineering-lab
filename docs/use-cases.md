# 用途と効果 / Use Cases

| ユースケース | 従来 | NUC導入後のメリット | 検証方法 |
|---|---|---|---|
| GitHub変更確認 | PCで都度アクセス | 定期取得・差分保存 | read-only定時実行 |
| 複数AI接続 | 個別APIで試験 | 共通Web UIで比較 | 1モデル接続 |
| OSS/MCP検証 | 開発PCを汚す | Dockerで再現・破棄 | サンプルAPIコンテナ化 |
| 死活監視 | 停止に気づかない | 停止履歴・通知 | 意図的な停止実験 |
| 外部GPU利用 | 都度手動 | 認証付きAPI経由で呼び出し | RunPod疎通 |
| 自動テスト | 手元で実行 | 信頼済みジョブを再実行 | 再現性確認 |

## 価値を測る
1か月運用後、手作業削減時間・ジョブ成功率・障害・API費用・保守工数を評価。利用頻度の低いサービスは停止。CPU上のLLM推論速度が足りなければ外部GPU/APIに任せる。

## 最初のワークフロー
1. 公開GitHubリポジトリの最新コミットメタデータを取得（read-only）。
2. 差分をMarkdownで保存。
3. 承認後、必要ならAI APIで要約。
4. Uptime Kumaでサーバーの状態を確認。

GPUもGitHub書き込み権限も不要な小さなPoCから始める。
